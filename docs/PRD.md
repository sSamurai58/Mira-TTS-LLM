# PRD

## Обзор продукта

**Mira** — локальная студия TTS + LLM: человек готовит свой голос и текст, обучает голосовую модель, получает озвучку и подключает её к другим своим проектам.

Имя выпуска: **Mira v1 — Studio Path**.

## Проблемы

- Текст для озвучки, запись, нарезка, обучение голоса и TTS живут в разных инструментах.
- Чужой TTS не звучит «своим» голосом; свой голос тяжело собрать в переиспользуемую модель.
- Готовую модель нельзя быстро вставить в другой проект (игра, бот, ролик) без ручного копирования файлов.

## Цели

- Один проходимый путь за сеанс: голос → нарезка → модель → текст → озвучка → экспорт/подключение.
- Голосовая модель — первоклассный артефакт: создать, обучить, импорт, экспорт.
- LLM помогает писать и править текст озвучки внутри того же пути.
- Другие проекты автора получают озвучку через локальный API/SDK, не через ручной экспорт каждый раз.

## Целевые пользователи

Первый человек: **создатель-разработчик**, который озвучивает собственные проекты и пишет для них тексты. Работает у себя на машине, голоса и модели — его активы.

Поверхность v1: **локальное desktop-приложение**.

Не цель v1: массовый SaaS для чужих студий, маркетплейс голосов, мобильная аудитория, браузерный клиент как основная оболочка.

## Ключевые фичи

### Этот выпуск (Mira v1 — Studio Path)

| Пункт | Проверка |
|---|---|
| Запись голоса с микрофона и импорт аудиофайлов в датасет | Человек добавляет семплы и видит их в списке датасета |
| Автонарезка на слова и фразы | После нарезки видны сегменты с границами; можно править/отклонить кусок |
| Обучение голосовой модели на нарезанном датасете | Появляется именованная модель со статусом «готова» |
| Импорт и экспорт голосовой модели | Модель уходит в файл/пакет и открывается обратно без потери имени |
| Ввод и LLM-генерация/правка текста озвучки | Человек получает текст, который можно отправить в TTS |
| TTS выбранной моделью | На выходе слышимый аудиофайл/превью своей моделью |
| Локальный API/SDK для других проектов | Из внешнего проекта вызывается озвучка той же моделью и приходит аудио |

### Следующий (уже понятный)

- Пакетная озвучка длинных сценариев и глав
- Эмоции / стиль / несколько дикторов в одном проекте
- Мультиязычные датасеты и модели
- Очередь обучения и мониторинг железа
- UI для нескольких рабочих мест (не только автор)

### Снаружи продукта

- Полноценная DAW и сведение музыки
- Видеомонтаж и таймлайн ролика
- Обучение foundation-LLM с нуля
- Маркетплейс чужих голосов
- Мобильное приложение в v1
- Облачный хостинг чужих аккаунтов как SaaS

## Решение продакта (сдача)

```text
Человек: Создатель-разработчик, который озвучивает свои проекты своим голосом и готовит для них тексты — часто, у себя на машине.
Работа: Собрать свой голос в модель, получить озвучку по тексту и подключить её к другим своим проектам.
Как делает сейчас:
  1. Пишет текст вручную или во внешнем чате.
  2. Читает в микрофон или берёт чужой TTS.
  3. Режет запись вручную в DAW / редакторе.
  4. Учит или настраивает voice-модель в отдельном пайплайне.
  5. Копирует аудио или веса в другие проекты руками.
Сломанный шаг: нет одного контура «текст + свой голос → модель → озвучка → вставка в проект».
Путь выпуска: Открыть Mira → записать или импортировать голос → автонарезка на слова/фразы → обучить модель → ввести или сгенерировать текст (LLM) → озвучить моделью → экспортировать модель/аудио и вызвать из другого проекта через локальный API/SDK.
Этот выпуск:
  - Датасет: запись и импорт — проверка: семплы видны в списке
  - Автонарезка слов/фраз — проверка: сегменты с границами на экране
  - Обучение голосовой модели — проверка: модель в статусе «готова»
  - Импорт/экспорт модели — проверка: пакет уходит и открывается обратно
  - Текст озвучки вручную и через LLM — проверка: текст уходит в TTS
  - TTS своей моделью — проверка: превью/файл своим голосом
  - Локальный API/SDK — проверка: внешний вызов возвращает аудио той же моделью
Следующий: пакетная озвучка; эмоции/стиль; мультиязычность; очередь обучения; мультипользовательский UI.
Снаружи: DAW; видеомонтаж; обучение LLM с нуля; маркетплейс голосов; мобильное приложение v1; чужой облачный SaaS.
Порядок: продакт → дизайнер (экраны пути) → бэкенд (датасет, сегменты, модель, TTS/LLM jobs, API) → специалист предмета (речь/датасет) → фронтенд → DevOps → тестировщик.
Открытый вопрос: нет (поверхность v1 = desktop; ответ пользователя 2026-11-15).
```
