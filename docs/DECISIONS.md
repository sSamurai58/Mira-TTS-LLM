# Decisions (ADR)

## ADR-1: Фокус v1 на Studio Path (TTS + LLM + свой голос)
- Дата: 2026-11-15
- Статус: принято
- Контекст: Запрос пользователя покрывает текст, запись, нарезку, обучение голоса, импорт/экспорт и подключение к другим проектам — объём легко расползается в DAW/SaaS.
- Решение: Первый выпуск — один путь Studio Path; DAW, видео, маркетплейс и мобильное — снаружи.
- Альтернативы: Сразу полноценная студия с монтажом; только API без UI; только чужой TTS без своей модели.
- Последствия: Дизайн и контракт строятся вокруг датасета, сегментов, модели, jobs и локального API.

## ADR-2: Поверхность v1 — desktop
- Дата: 2026-11-15
- Статус: принято
- Контекст: Нужна первая оболочка для Studio Path; кандидат — desktop или локальный веб.
- Решение: Локальное desktop-приложение как единственная поверхность v1.
- Альтернативы: Веб-сервис у себя на машине; сразу обе оболочки.
- Последствия: Дизайн — window shell + шаг-навигатор; стек UI/рантайма выбирает бэкенд/фронтенд под desktop; мобильное и браузерный SaaS остаются снаружи.

## ADR-3: Локальный studio-api на FastAPI + SQLite
- Дата: 2026-11-15
- Статус: принято
- Контекст: Desktop нужен локальный контракт для датасета, jobs, модели, TTS/LLM и внешнего API; ML-стек удобен в Python.
- Решение: Один процесс `services/studio-api` (FastAPI), данные в `~/.mira`, контракт в `docs/CONTRACT.md`. Segment/train v1 — stub; TTS render — interim `edge-tts` (+ffmpeg), не клон датасета.
- Альтернативы: Встроить всё в Electron main; отдельный Rust-core; облачный backend.
- Последствия: Фронтенд ходит только в `/v1`; voice-clone ML worker подменяет stub без смены имён полей.

## ADR-4: Desktop UI — Electron + React (Vite)
- Дата: 2026-11-15
- Статус: принято
- Контекст: Нужна desktop-оболочка под DESIGN с шагом-навигатором и вызовами studio-api.
- Решение: `apps/desktop` на Electron + React + Vite; renderer ходит в локальный `/v1` (proxy на studio-api).
- Альтернативы: Tauri; чистый Qt; только браузер без окна.
- Последствия: Запуск — API + `npm run desktop`; стек UI зафиксирован для v1.

## ADR-5: CI на GitHub Actions
- Дата: 2026-11-15
- Статус: принято
- Контекст: Нет пайплайна; перед релизом нужны проверка API smoke и сборка desktop.
- Решение: Workflow `.github/workflows/ci.yml` на PR и push в main: studio-api smoke + desktop typecheck/build + artifact renderer.
- Альтернативы: Только локальные скрипты; облачный деплой SaaS.
- Последствия: Красный CI блокирует уверенность в merge; production по-прежнему через явный tag после тестировщика.

## ADR-6: Автообновление desktop через GitHub Releases
- Дата: 2026-11-15
- Статус: принято
- Контекст: Нужны проверка релиза, фоновое скачивание и перезапуск без ручной переустановки.
- Решение: `electron-updater` + publish `electron-builder` на GitHub Releases по тегам `mira-v*`; UI — UpdateBanner + кнопка на Подключении.
- Альтернативы: Только ручная скачка; собственный update-server; тихий install без подтверждения.
- Последствия: Production-теги обязаны публиковать артефакты updater (`latest*.yml`); в dev-режиме проверка сообщает, что нужен packaged build.
